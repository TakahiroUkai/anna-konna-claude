大きな作業を、チェックリストに分けて進める

一度では終わらない大きな作業を、段階に分け、各段階に「終わりの条件」をつけて進める方法です。最後に進捗メモを作らせ、会話が変わっても続きから始められます。確かめるのは自分です。

結論から書きます。大きな作業は、「何をするか」の一覧より先に、段階ごとの「終わりの条件」を決めます。終わりの条件があると、段階を終えたかどうかを、あなたが確かめられます。

「社内の勉強会を任されたが、何から手をつけるか分からない」。そんな同僚に、そのまま見せられる方法です。基本のチャットだけで試せます。

ねらい

  • 大きな作業を、4〜6の段階に分けます。
  • 各段階に、「終わりの条件」と「自分で確かめる方法」をつけます。
  • 一度に全部をやらせず、1段階ずつ進めます。
  • 会話が長くなっても、「進捗メモ」で続きから始められるようにします。

公式のドキュメントには、順序が大事なときは番号つきの手順で頼むこと、答えを出す前に確かめさせること、理由や背景を添えることが書かれています。この記事の方法は、それらの考え方を、作業の進め方に当てはめた1つの例です。長い作業を、複数の会話にまたがって進める際の公式の説明は、主にコードを書く作業向けです。この記事の「進捗メモ」は、その考え方を、ふつうの作業に当てはめたものです。

準備するもの

  • 大きな作業を1つ(例: 社内勉強会を開く、引っ越しの手続きを進める、レポートを書き上げる)。
  • 締め切りと、使える時間。
  • 個人名、住所、社外秘の内容は入れず、「Aさん」「会場」のように置き換えます。

手順

  1. 最初のプロンプトで、段階と終わりの条件を出してもらいます。
  2. 出てきた一覧を、そのまま信じず、順番と抜けを見直します。
  3. 1段階ずつ、作業を頼みます。終わるたびに、終わりの条件を満たしたかを、自分で確かめます。
  4. 区切りで、進捗メモを作ってもらいます。メモは、手元のメモ帳などに保存します。
  5. 新しい会話では、進捗メモを貼って、続きから頼みます。

使いどころと失敗例

向く場面は、数日から数週間かかる作業で、手順が頭の中に収まらないときです。作業の抜けと、順番の間違いを、早めに見つけたいときにも向きます。

向かない場面は、30分で終わる作業です。段階に分ける手間のほうが大きくなります。また、締め切りの日付、契約、お金に関わる判断は、チェックリストが完成しても、自分で確かめます。

よくある失敗と、その直し方です。

  • 終わりの条件が甘い。 「資料ができている」では確かめられません。「項目が5つ以内で、各項目に時間が割り当てられている」のように、数えられる形に直します。
  • 一度に全部をやらせる。 途中の間違いに気づけません。「最初の段階だけ進める」と、プロンプトに入れます。
  • Claudeの「終わりました」を、そのまま信じる。 確かめるのは、あなたです。成果物を貼って、条件と照らし合わせます。
  • 進捗メモを保存しない。 会話が変わると、続きが分からなくなります。メモは、手元のメモ帳などに残します。

うまくいかないとき

  • 段階が多すぎるとき: 「段階は6つまで」と書いて、頼み直します。
  • 段階の順番がおかしいとき: 「段階3は、段階2より先にできないか」のように、理由つきで聞きます。
  • 会話をまたぐと、決めたことが変わるとき: 進捗メモの「決めたこと」に、理由を書いて貼ります。
  • 安全面: 進捗メモには、個人名、住所、社外秘の内容を入れません。入れる場合は、会社の決まりを確かめてから、貼ります。
  • 時間の見積もりが当たらないとき: 見積もりは目安です。1段階を実際にやった時間を伝えて、残りを見直してもらいます。

つぎに試すなら

  • 「質問してから答えて」と頼んで、条件を詰める

    答えを頼む前に、「先にあなたから質問して」と頼む方法です。決まっていないことをClaudeに聞き出してもらい、条件が固まってから答えてもらいます。
