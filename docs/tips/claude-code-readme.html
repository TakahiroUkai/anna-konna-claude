結論から書きます。READMEは、Claudeに書かせて終わりにしません。README に書かれたコマンドを、そのまま実際に動かして、動いたものだけを残します。 書かせるのは1分、確かめるのが本番です。

「自分で作った道具の使い方を、半年後の自分が思い出せない」。そんな同僚や、仲間に道具を渡す前の友人に、そのまま見せられる方法です。

ねらい

  • READMEと、Claude用のメモである CLAUDE.md の役割の違いが分かります。
  • Claude Codeに、コードを読ませてREADMEを書かせ、書かれた手順を実際に動かして確かめられます。
  • 秘密の情報(パスワード、鍵、個人情報)を、READMEに載せないための点検ができます。

準備するもの

  • Claude Code(コードを書く、動かす作業をClaudeに任せる道具)を使える状態。
  • READMEを付けたい、小さなプロジェクトのフォルダ。動くコードと、テストがあると確かめやすくなります。前の記事「Claude Codeで、小さなスクリプトを作る」の作品でも試せます。
  • gitで管理していること。書き換えを、あとで見比べて戻せるようにします。
  • 5〜10分の、確かめる時間。

READMEと CLAUDE.md は、読む人が違う

README(リードミー)は、プロジェクトの説明書で、人が最初に読みます。一方、CLAUDE.md(クロード・エムディー)は、Claudeが、作業を始めるたびに読む指示のファイルです。公式のドキュメントでは、CLAUDE.md は毎回の作業の最初に読み込まれ、「強制」ではなく、参考にする文脈として扱われる、と説明されています。

Claude Codeには、/init というコマンドがあります。公式の説明では、プロジェクトを読んで、CLAUDE.md の最初の案を作ります。すでにCLAUDE.md があるときは、上書きせず、改善案を出す、と書かれています。READMEを書かせる作業とは、別のものです。この記事では、READMEだけを扱います。

手順

  1. Claude Codeを、そのフォルダで起動する。 権限モードを、画面の下の表示で確かめます。READMEを書く間、ファイルの書き込みの許可は、1回ずつ内容を見て出します。
  2. 下のプロンプト1で、READMEを書かせる。 「コードに書かれていないことは書かない」と、条件に入れます。
  3. 書かれたコマンドを、自分で1つずつ動かす。 プロンプト2で、Claudeにも実行させ、コマンドと出力を提出してもらいます。自分の目でも、1つは動かします。
  4. 秘密の点検をする。 プロンプト3で、READMEとフォルダ全体を調べさせます。
  5. 差分を見る。 git diff で、READMEのどこが増えたかを見ます。意図しない所が変わっていないかを確かめます。

そのまま使えるプロンプト

実際の出力例

前の記事の、小さなスクリプトのフォルダで、プロンプト1に近い内容でREADMEを作り、書かれたコマンドを実際に実行した記録です。作った環境は、Claude Codeの画面ではなく、クラウド上の作業場所で、Claudeが書いて実行したものです。READMEの文面は、毎回同じにはなりません。

READMEの「注意」に、「割合は四捨五入しているため、合計が100%にならないことがある」と書きました。これは、実行結果(68%、22%、11%)を見て、あとから足した一文です。コードだけを読んでも、気づきにくい点です。実際に動かして、初めて書ける注意もあります。

使いどころと失敗例

向く場面は、動くコードがあり、使い方を人に伝える必要があるときです。半年後の自分に向けた説明書としても、使えます。

向かない場面は、まだ作りかけで、動かし方が毎日変わるプロジェクトです。READMEが、すぐに古くなります。

よくある失敗と、その直し方です。

  • 動かさずに、READMEを信じる。 書かれたコマンドが、書かれたとおりに動くとは限りません。プロンプト2で、実行と出力の提出を求めます。公式の「Best practices」でも、実行したコマンドと、その出力を求める使い方が紹介されています。
  • コードにない機能が、書かれている。 「コードに書かれていないことは書かない」と条件に入れます。READMEの文を1つずつ、コードの場所と照らします。
  • 秘密の情報が、混ざる。 READMEは、公開する前提で読み直します。公式のドキュメントには、設定の deny ルール(Claudeに許可しない操作を決める設定)で、.env のようなファイルの読み込みを止める例があります。書き方は、公式の「Configure permissions」を見ます。
  • CLAUDE.md の内容を、READMEに混ぜる。 「Claudeへの指示」は、READMEに書きません。人向けの説明と、Claude向けの決まりは、ファイルを分けます。

うまくいかないとき

  • READMEが長すぎるとき: 「全体で40行以内」のように、行数を条件に入れて、書き直させます。
  • コマンドが、環境によって動かないとき: 動かした環境(OS、Pythonの版)を、READMEの「必要なもの」に書きます。確かめていない環境のことは、書きません。
  • Claudeが、動かさずに「確認しました」と書くとき: 出力の全文を貼るよう、求め直します。
  • 秘密らしき文字列が見つかったとき: すでにコミットしたものは、履歴にも残ります。扱いは、使っているサービスの手順と、会社の決まりで確かめます。
  • 画面の表示や、コマンドの名前は変わることがあります。使う前に、公式のページを開き直します。
