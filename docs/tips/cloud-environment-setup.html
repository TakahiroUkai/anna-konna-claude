Claude Codeのクラウド環境を、初心者が失敗せずに設定する

Claude Codeのクラウドセッションが動く「環境」の設定を、いつ必要か、なぜ必要か、どう設定するかに分けて解説します。ネットワークアクセス、環境変数、セットアップスクリプト、秘密の鍵の扱いと、よくある誤った設定の例も載せました。

Claude Codeには、クラウド上の仮想マシンでClaudeに作業をさせる「クラウドセッション」があります。そのセッションが動く場所の設定を、環境と呼びます。結論は1つです。ふだんは初期設定のままで足ります。足りなくなったときだけ、足りない所を1つずつ足します。

ねらい

  • 環境とは何か、いつ触る必要があるのかが分かります。
  • 4つの設定(ネットワークアクセス、環境変数、ネットワークシークレット、セットアップスクリプト)の役割が分かります。
  • よくある誤った設定を知って、保存前に自分で点検できるようになります。

準備するもの

  • クラウドセッションを使えるプラン。公式ドキュメントでは、Pro、Max、Ultra、Teamのプランと、Enterpriseの一部の席で使えると説明されています(確認日時点)。
  • すでにクラウドセッションを始められる状態(GitHubとの連携など)。始め方は、公式の入門ページにあります。
  • 環境に何を足したいかのメモ。例:「このドメインに接続したい」「このツールを入れたい」。

環境とは何か

クラウドセッションは、セッションごとに新しい仮想マシン(VM)で動きます。公式ドキュメントでは、OSはUbuntu 24.04で、リポジトリがコピーされた状態で始まり、よく使う開発ツールがすでに入っている、と説明されています。仮想マシンとは、クラウド上に用意される、作業用の小さなパソコンのようなものです。

環境は、その仮想マシンの「始まり方」を決める設定です。

初期設定の環境は「Default」です。公式ドキュメントでは、Defaultは次のような状態だと説明されています。

  • ネットワークアクセスは「Trusted」です。パッケージの配布先など、許可リストにあるドメインにだけ接続できます。
  • 環境変数もセットアップスクリプトも、何も入っていません。

クラウドセッション: 自分のパソコンではなく、クラウド上のパソコンでClaudeに作業させる使い方です。

環境: そのクラウド上のパソコンの、始まり方を決める設定のまとまりです。

仮想マシン(VM): クラウド上に用意される、作業用のパソコンです。セッションごとに新しいものが使われます。

リポジトリ: 作っているプログラムや文書の、ファイルと変更の記録をまとめて置く場所です。

許可リスト: 接続してよい相手を並べた一覧です。ここにない相手には接続できません。

ドメイン: 「example.com」のような、インターネット上の住所の名前です。

パッケージ: 他の人が作った、部品のようなプログラムです。プログラムを作るときに取り込んで使います。

セッション: Claudeに作業を頼み始めてから終わるまでの、ひとまとまりのやりとりです。

GitHub: プログラムなどを保管し、共同で使うためのサービスです。

いつ設定が必要か

公式ドキュメントには、初期設定で足りないときに環境を設定する、と書かれています。具体的には次の3つの場面です。

どれにも当てはまらないなら、触らなくて大丈夫です。最初は初期設定のまま試して、困った所を1つだけ直すのが安全です。

設定の画面の開き方

公式ドキュメントの案内は、次のとおりです。画面の表示は変わることがあります。

環境の選択は、セッションの最初のメッセージを送るまでしか出ません。動いているセッションの環境を直すときは、セッション名の横の矢印から「Edit cloud environment」を選びます。自分で作った環境は、自分のアカウントだけで使えます。

4つの設定を、1つずつ理解する

ネットワークアクセス

外に接続してよい範囲を、4段階から選びます(公式ドキュメント)。

Customでは、「Allowed domains」に1行1ドメインで書きます。先頭の *. は、そのドメインのすべてのサブドメインを指します。

どの段階を選んでも、GitHub(専用の中継を通る)と、有効にしたMCPコネクタは使えます。ネットワークアクセスを変えると、動いているセッションにも1分ほどで反映されます(公式ドキュメント)。

ここからは、私の考え方です。広い設定が必要な理由が見つかるまでは、Trustedのまま使い、足りないドメインだけCustomで足すほうが、あとで見直しやすくなります。

サブドメイン: 「api.example.com」の「api」のように、ドメインの前に付く名前です。「*.example.com」と書くと、すべてのサブドメインを指します。

Allowed domains: 接続を許すドメインを書く欄です。

SDK: あるサービスを自分のプログラムから使うための、部品と道具のまとまりです。

MCPコネクタ: Claudeを外部のサービスにつなぐ仕組みです。通信はAnthropicのサーバーを通ります。

環境変数

セッションに最初から渡しておく、設定値です。KEY=value の形で、1行に1つ書きます。

覚えておくことが3つあります。

  • # を含む値は、引用符で囲みます。囲まないと、# から後ろがコメントとして消えます。
  • 変数を直しても、動いているセッションには、すぐには反映されません。VMがアイドルのあとに復元されるか、作り直されるときに読み直されます。すぐに使いたいときは、新しいセッションを始めます。
  • 同じ環境を使う人は、全員が値を読めます。鍵は書かないでください。

環境変数: プログラムが読む、名前つきの設定値です。「LOG_LEVEL=debug」なら、名前が「LOG_LEVEL」、値が「debug」です。

引用符: 文字列の両端を囲む「"」や「'」です。値の途中の「#」が、コメントと誤解されるのを防ぎます。

コメント: プログラムが読み飛ばす、人間向けのメモの部分です。「#」から行の終わりまでが、これにあたります。

アイドル: しばらく何も操作がなく、休んでいる状態です。アイドルのあとにVMが復元されると、変数が読み直されます。

ネットワークシークレット

APIキーやトークンを、Claudeに見せずに使わせる仕組みです。公式ドキュメントでは、Anthropicの中継(エージェントプロキシ)が、指定したホスト宛ての通信にだけ鍵を付ける、と説明されています。鍵は仮想マシンの外に残ります。

追加する手順の要点は次のとおりです。

  • 環境の編集画面で「Network secrets」の行を開き、「Add secret」を選びます。
  • 名前、使うホスト(例:api.example.com)、鍵を入れるヘッダーと値を書きます。
  • 保存後は、値をもう一度見ることはできません。変えるときは、消して入れ直します。
  • 確かめるときは、そのAPIをClaudeに呼ばせます。環境変数やファイルに鍵が出ないことも分かります。

鍵を付けてもらえない通信もあります。GitHub(専用の中継が別に認証します)、Anthropic API、npmやPyPIなどの公開のパッケージ配布先は、対象外です。

APIキー・トークン: サービスを使う権利を示す、合い言葉のような文字列です。他人に知られると、勝手に使われるおそれがあります。

ホスト: 接続先のコンピューターの名前です。例:「api.example.com」。

ヘッダー: 通信に付ける、追加情報の欄です。鍵は、ここに入れて送ります。

エージェントプロキシ: 通信を中継するAnthropicの仕組みです。指定した相手宛ての通信にだけ、鍵を付けます。

Bearer: 「この鍵を持つ人」として扱ってほしい、という種類の鍵の送り方です。

セットアップスクリプト

作業の前に、一度だけ動かす、Bashのスクリプトです。入っていない道具を入れるときに使います。root権限で動くので、apt install も使えます。

守る決まりが4つあります(公式ドキュメント)。

  • 終了コードは0にします。0以外だと、セッションが始まりません。大事でない命令には、|| true を付けます。
  • 合計で、おおよそ5分以内に終わらせます。超えると、環境のキャッシュが作られません。
  • インストールには、ネットワークが要ります。Noneでは失敗します。
  • 環境変数は、まだ設定されていません。スクリプトで使う値は、スクリプトの中に書きます。

キャッシュとは、セットアップ後のディスクの状態を保存して、次回から再利用する仕組みです。入れたツールやイメージは残ります。起動したデータベースなど、動いているものは残りません。キャッシュの作り直しは、スクリプトや許可ホストを変えたときと、約7日で期限が切れたときに行われます。

Bash: コマンドを順に実行するための、文字で操作する道具(シェル)です。

root: パソコンのすべてを変更できる、最も強い権限です。

apt: Ubuntuというパソコンのソフトを入れる道具です。「apt install」で入れます。

終了コード: コマンドが終わったときに返す数字です。0は成功、それ以外は失敗を表します。

「 | | true」: 直前のコマンドが失敗しても、成功したことにして先へ進める書き方です。

キャッシュ: 作業後の状態を保存して、次回から使い回す仕組みです。

並列(& と wait): 複数の作業を同時に走らせて、全部終わるのを待つ書き方です。

Dockerイメージ: アプリをそのまま動かせる形にまとめた、ひな形のファイルです。

よくある誤った設定の例

どれも、公式ドキュメントに書かれている動作から導いた例です。実際の画面の表示や挙動は、変わることがあります。

Trusted / Full / Custom / None: ネットワークアクセスの4つの段階です。上の表を見てください。

npm・PyPI: プログラムの部品を配っているサービスです。npmはJavaScript用、PyPIはPython用です。

フック: 決まった場面で、自動で動かす小さな処理です。

~/.claude/: 自分のパソコンの中にある、Claude Codeの個人用の設定を置く場所です。

手順

そのまま使えるプロンプト

保存前の点検リスト

  • 初期設定で試して、困った所を1つ決めた。
  • 鍵を、環境変数に書いていない。
  • スクリプトは終了コード0で、5分以内に終わる。
  • スクリプトは、環境変数に頼っていない。
  • インストールがあるなら、ネットワークアクセスはNoneでない。
  • 新しいセッションで、実際に動かして確かめた。

注意すること

  • 同じ環境を使う人は、環境変数とセットアップスクリプトを読めます。個人の情報や鍵を書かないでください。
  • 用意されている資源の目安は、4つの仮想CPU、16GBのメモリ、30GBのディスクです。公式ドキュメントには、この値は変わることがある、と書かれています。
  • コマンドの待ち時間にも上限があります。大きな作業は、小さく分けて頼みます。
  • Teamなどの共有環境は、管理者(Owner)が管理します。権限がないときは、管理者に頼みます。

vCPU: 仮想マシンが使える、計算をする部品の数です。多いほど、同時に多くの処理をこなせます。

メモリ: 作業中のデータを一時的に置く場所です。足りないと、重い作業が止まることがあります。

ディスク: ファイルを保存しておく場所です。

Owner: 組織の設定を管理できる役割です。Teamなどのプランで使われます。

うまくいかないとき

  • セッションが始まらないとき: セットアップスクリプトが、0以外で終わっていないか確かめます。
  • 起動が遅いとき: スクリプトが約5分を超えて、キャッシュされていない可能性があります。
  • 接続できないとき: ネットワークアクセスの段階と、許可リストのドメインを確かめます。GitHubとMCPコネクタは、別の経路で使えます。
  • 鍵を足したのに、通信に付かないとき: 一覧に「Not sent」と出ていないか確かめます。表示の理由に従います。
  • 設定を変えたのに反映されないとき: 新しいセッションで試します。
