定期タスクが失敗したときの、切り分けの順番

定期タスク(決まった時間に自動で動く依頼)が動かない、途中で終わる、というときの確かめ方を、公式のヘルプで確かめた範囲で整理します。公式に書かれていない点は、書かれていないと分けて載せます。

結論から書きます。定期タスクが思いどおりに動かないときは、指示文をいじる前に、「動いたか」「計算機が要る設定か」「承認で止まっていないか」の順に確かめます。公式のヘルプには、定期タスクは、普通は自分のパソコンが寝ていても動くと書かれています。それが当てはまらない設定が、いくつかあります。

「毎朝のまとめを頼んだのに、届いたり届かなかったりする」という同僚に、この順番のチェック表を見せられます。

ねらい

  • 定期タスク(Coworkで、決まった時間に自動で動く依頼)の失敗を、順番に切り分けます。
  • 承認で止まる場合と、パソコンが必要な場合を、見分けます。
  • 公式に書かれていない点は、書かれていないと分かった上で、確かめ方を決めます。

準備するもの

  • 動かない、または途中で終わる定期タスクが1つ。
  • 公式のヘルプには、定期タスクは、Pro、Max、Ultra、Team、Enterpriseで使えると書かれています。Freeは載っていませんでした。
  • 20分ほどの時間。

手順

  1. 動いたかを、実行の一覧で見ます。 公式のヘルプには、左のサイドバーの「Scheduled」で、これからの実行と過去の実行を見られると書かれています。1回の実行は、それぞれ独立したCoworkのセッションとして動くと書かれています。履歴がどれくらい残るかは、確認できませんでした。
  2. 一時停止になっていないかを見ます。 公式のヘルプには、タスクを開くと、指示文・頻度・承認モードを直せ、一時停止、再開、削除、今すぐ実行ができると書かれています。
  3. パソコンが必要な設定かを見ます。 公式のヘルプには、フォルダを選ぶと「Require this computer」がオンになり、その場合は、パソコンが起きていて、Claude Desktopが開いている間だけ動くと書かれています。それ以外は、パソコンが寝ていても、アプリを閉じていても、決めた頻度で動くとあります。
  4. 承認で止まっていないかを見ます。 公式のヘルプには、コネクタのツールが「Always ask」に設定されていると、定期タスクは、あなたの答えを待つか、そのツールを使わずに終わることがあると書かれています。
  5. 今すぐ実行で、再現します。 公式のヘルプにある「今すぐ実行」で、同じ指示文を動かし、どこで止まるかを見ます。

定期タスクの失敗を直すための専用の手引きは、確認できた2つのページにはありませんでした。実行を逃したときの動き、履歴の保存期間、タスクの数の上限も、確認できませんでした。上の順番は、書かれている仕様から組み立てた、確かめ方の案です。

そのまま使えるプロンプト

実際の出力例

この記事を書いた環境では、読者の定期タスクを使って動かすことができませんでした。作り話の出力を載せないため、出力は載せません。

自分のタスクで試すときの確かめ方です。

  • 質問に1つずつ答え、「Scheduled」の画面と見比べます。
  • 答えるたびに、疑う所が減っているかを確かめます。
  • 原因が分かったら、直した設定を、タスクの名前の横にメモします。

使いどころと失敗例

向く場面は、毎週のまとめなど、決まった作業が、ときどき動かないときです。

向かない場面は、一度も動いたことがないタスクです。その場合は、作り方の手順に戻ります。

よくある失敗と、その直し方です。

  • 指示文だけを何度も直す。 原因が承認や設定にあると、指示文を直しても変わりません。先に設定を見ます。
  • 「Always ask」を、そのままにして、無人で動かす。 答え待ちになる場合があります。公式のヘルプには、承認モードをManualにして「Allow for all scheduled runs」を選ぶと、問い合わせなしで使えると書かれています。ただし、許可は広がります。何を許すのかを決めてから、選びます。
  • 承認モードを、確認なしで「Skip」にする。 公式のヘルプには、Skipは承認の確認なしで動くと書かれています。削除や外部への送信を含む作業には、向きません。
  • 個人の金融情報を、定期タスクに使おうとする。 公式のヘルプには、定期タスクは、Personal Financeの連携口座を使えないと書かれています。

うまくいかないとき

  • 実行の記録が見つからないとき: 「Scheduled」を開いて、タスクが一時停止になっていないかを確かめます。見つからなければ、作り直す前に、タスクを作った画面(「/schedule」)を確認します。
  • パソコンを閉じていた日だけ動かないとき: 「Require this computer」が、オンになっていないかを確かめます。フォルダを選んだタスクで、オンになると、公式のヘルプに書かれています。
  • ローカルのファイルやブラウザを使うとき: 公式のヘルプには、ローカルのファイル、ブラウザ、パソコンの操作を使う作業は、デスクトップアプリが必要と書かれています。
  • 安全面: 無人で動くので、削除、送信、お金に関わる操作を含む作業は、最初は人が見る設定(Manual)で試します。ファイルの完全な削除の前に確認が入る機能(Deletion protection)があると書かれていますが、定期タスクでどう動くかは、確認できませんでした。
  • 画面の表示は変わることがあります。 くわしくは、公式のヘルプで、いまの内容を確かめてください。
