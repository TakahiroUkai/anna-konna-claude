Claude Codeで、小さなスクリプトを作る

Claude Codeに、小さなスクリプトを作らせる手順です。先に計画だけを出させ、テストで合否を確かめ、実行結果を見せてもらいます。ファイルを変える許可の出し方と、元に戻す方法まで書きました。

結論から書きます。Claude Codeに小さなスクリプトを任せるときは、次の順で進めます。先に計画だけ出させる。作らせる。テストを走らせて、合否を見る。 この3つで、「動いたように見える」だけのコードを避けられます。

「毎月の支出CSVを、手で集計している」。そんな同僚や、家計簿の表を毎月眺めている家族に、そのまま見せられる手順です。

ねらい

  • Claude Code(コードを書く、動かす作業をClaudeに任せる道具)で、小さなスクリプトを作る一連の流れが分かります。
  • 「計画だけ出させる」「合否が返る確認を渡す」の2つの使い方が身につきます。
  • ファイルを変えられる道具を使うときの、許可の出し方と、元に戻す方法が分かります。

準備するもの

  • Claude Codeを使える状態。入れ方とプランは、公式の入門ページで確かめます。この記事で読んだ公式ページには、必要なプランの一覧は見つかりませんでした。
  • 作業用の空のフォルダ。大事なファイルがあるフォルダでは試しません。
  • gitを入れて、そのフォルダを管理しておく。公式のヘルプには、変更をコミットするまでは、gitで元に戻せると書かれています。gitとは、ファイルの変更の履歴を残す道具です。
  • 試し用のCSV。この記事では、日付、店名、カテゴリ、金額の4列の、作り物の支出表を使います。実際の口座や顧客の情報は使いません。

手順

  1. 作業フォルダでClaude Codeを起動する。 起動したら、画面の下の表示で、いまの権限モードを確かめます。権限モードとは、ファイルの変更やコマンドの実行を、聞かずにやってよいかの設定です。起動時のモードは版によって違う、と公式に書かれています。
  2. プランモードにする。 プランモードでは、Claudeはファイルを読んで計画を出しますが、計画を承認するまで、ファイルは変えません。入り方は、Shift+Tabで切り替える、/plan を頭につける、claude --permission-mode plan で起動する、の3つです。
  3. 下のプロンプトで、計画を出させる。 出てきた計画は、読んで直します。「テストの置き場所」「CSVの列名」が合っているかを見ます。
  4. 計画を承認して、作らせる。 ファイルを変えるたびに許可を聞かれます。内容を見てから「Yes」を選びます。
  5. テストの結果を、そのまま見せてもらう。 「通りました」という文ではなく、実行したコマンドと、その出力を出してもらいます。
  6. 自分でも動かす。 手で計算した数字と、見比べます。
  7. コミットする。 ここで元に戻せる状態になります。

そのまま使えるプロンプト

実際の出力例

このプロンプトの1と2と同じ内容で、スクリプトとテストを作り、実行した結果です。作った環境は、Claude Codeの画面ではなく、クラウド上の作業場所で、Claudeが書いて、そのまま実行したものです。画面や、Claudeの説明の言い回しは、Claude Codeとは違います。コードは毎回同じにはなりません。CSVは、本文の4列の形で、6行の作り物です。

割合を足すと、68%+22%+11%で101%になります。四捨五入のためで、計算の間違いではありません。ただ、こういう点は、自分の目で見ないと気づけません。実行の結果は、必ず自分でも読みます。

使いどころと失敗例

向く場面は、入力と出力がはっきりした、小さな作業です。CSVの集計、ファイル名の一括変更、決まった形式への変換などです。合否が返るテストを作れるので、Claudeに任せやすく、確かめやすい作業です。

向かない場面は、仕様があいまいな作業と、元に戻せないものを触る作業です。本番のデータや、消すと困るファイルがあるフォルダでは、試しません。

よくある失敗と、その直し方です。

  • テストを作らせずに、「動いた」で終わる。 公式の「Best practices」では、合否が返る確かめ方(テスト、ビルドの終了コード、出力の比較など)を渡すとよい、と説明されています。プロンプト2のように、実行と出力の提出を頼みます。
  • 許可の確認を、見ずに通す。 「今後は聞かない」を選ぶと、そのルールは、リポジトリの .claude/settings.local.json に保存される、と公式に書かれています。/permissions で、保存されたルールを見直せます。
  • 直しを、何度もくり返して、混乱する。 公式では、2回直しても直らないときは、/clear で会話を空にして、書き直したプロンプトで始めるとよい、と説明されています。
  • 途中で止めたい。 Escで、Claudeの作業を止められます。止めたところまでの作業は残ります。

うまくいかないとき

  • プランモードに入れないとき: 画面の下の表示を見ながら、Shift+Tabを押します。入れないときは、claude --permission-mode plan で起動し直します。
  • テストが、何度やっても通らないとき: テストのほうが間違っていることもあります。テストが確かめている内容を、日本語で説明してもらいます。
  • 「ファイルが見つからない」と出るとき: 起動したフォルダに、CSVがあるかを確かめます。ファイル名の大文字・小文字や、全角の文字も見ます。
  • 日本語が文字化けするとき: CSVの文字コードが、UTF-8でない可能性があります。プロンプトに、文字コードを書きます。
  • gitを使っていないとき: 変更を戻す手段がありません。先に、作業フォルダでgitの管理を始めてから、試します。
  • 画面の表示や、モードの名前は変わることがあります。使う前に、公式のページを開き直します。
