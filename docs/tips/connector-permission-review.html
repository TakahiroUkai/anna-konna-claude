コネクタの権限を見直して、渡す範囲を絞る

Claudeにつないだコネクタを一覧にして、使っていないものを外し、読むだけで足りるものと、書き込みまで要るものを分けます。公式で確かめられた設定の範囲と、確認できなかった点まで整理します。

結論から書きます。コネクタは、つなぐと「Claudeが、そのサービスのデータにアクセスして、場合によっては変更もできる」状態になります。公式のヘルプセンターには、必要で信頼できるものだけをつなぎ、使わなくなったものは切る、と書かれています(2026年11月18日に確認)。月に1回、点検表を作って見直す習慣をおすすめします。

「便利そうで、いろいろつないだまま忘れている」という同僚に、そのまま見せられる点検です。

ねらい

  • つないだコネクタ(Claudeを他のアプリにつなぐ仕組み)を、一覧にします。
  • 使っていないものを切り、残すものは「読むだけで足りるか」を決めます。
  • 設定で変えられる範囲と、確認できなかった範囲を、先に分けておきます。

準備するもの

  • 設定画面を開けるClaudeのアカウント。公式のヘルプセンターによると、設定の場所は「Customize > Connectors」です。
  • 点検表を書く場所(メモ、スプレッドシートなど)。
  • 組織(TeamやEnterprise)のアカウントの人は、管理者(Owner)が決めている設定があります。自分で変えられない項目は、管理者に確かめます。
  • 個人情報や、社外に出せない情報は、点検表に書きません。サービス名と、使い道だけを書きます。

手順

  1. 一覧にします。 「Customize > Connectors」を開くと、つないだサービスが「Connectors」の欄に並びます。公式のヘルプセンターには、サービスごとに、切断、接続設定の変更、権限とアクセスレベルの確認ができると書かれています。
  2. 使い道を1行で書きます。 書けないものは、使っていない可能性が高いです。
  3. 使っていないものを切ります。 公式のヘルプセンターには、使わなくなったサービスは切断するよう書かれています。必要になったら、また、つなげます。
  4. 範囲を確かめます。 各コネクタのページには、読み書きできる内容(read/write)が出る、と書かれています。読むだけで足りる使い方なら、書き込みまでできる状態は、広すぎるかもしれません。
  5. 動作を確かめます。 絞ったあと、頼みたいことが、今までどおり動くかを見ます。

画面の表示は変わることがあります。

そのまま使えるプロンプト

実際の出力例

この記事を書いた環境では、Claudeの設定画面を操作して、実際に権限を絞り、動作を確かめることができませんでした。そのため、実際の出力は載せません。

自分で試すときは、次の点で確かめます。

  • 点検表の「切る」の行が、自分が使っていないと思うコネクタと一致しているか。
  • 「未記入」の欄を、Claudeが推測で埋めていないか。
  • 絞ったあと、読むだけの依頼ができて、書き込みの依頼が止まるか(止まる動きは、サービスや設定で違うことがあります)。

使いどころと失敗例

向く場面は、コネクタを3つ以上つないだとき、仕事用と個人用のアカウントが混ざっているとき、定期的に見直したいときです。

向かない場面は、まだ1つも試していないときです。先に、「コネクタで、予定を見ながら1日の計画を立てる」のような活用方法で、読み取りの動きを確かめてから、範囲を決めます。

よくある失敗と、その直し方です。

  • 切ったあと、必要なときに動かない。 もう一度つなぎます。公式のヘルプセンターには、認証がうまくいかないとき、切って、つなぎ直す方法が書かれています。
  • 自分で権限が変えられない。 組織のアカウントでは、Ownerが、組織全体の設定をしている場合があります。公式には、その設定は個人が上書きできないと書かれているので、管理者に頼みます。
  • 自作のカスタムコネクタを、よく確かめずにつなぐ。 公式のヘルプセンターには、カスタムコネクタはAnthropicが確認していないサービスにつなぐもので、信頼できる組織のものだけにして、権限をよく確かめる、と書かれています。
  • 共有の認証情報で動くカスタムコネクタ。 公式には、その認証情報でアクセスできる範囲に届く、と書かれています。広い範囲の認証情報を渡していないか、確かめます。
  • つないだサービス側の扱いを見ない。 公式には、つないだサービスは、自分の設備と規約でデータを処理し、場所が米国の外のこともある、と書かれています。サービス側の規約も、見ます。

外部のサービスから読み込んだ文章の中に、Claudeへの命令のような文が紛れ込む問題(プロンプトインジェクション)について、この記事で読んだ公式のページには、書かれていませんでした。一般的な注意として、読み取りだけで足りる用途は、書き込みの権限を渡さない、が安全側の考え方です。これは、この記事の著者の考えで、公式の説明ではありません。

うまくいかないとき

  1. コネクタの一覧に、つないだ覚えのないものがある。 組織のアカウントの場合は、管理者に確かめます。個人のアカウントで、覚えがないときは、切断して、アカウント側のパスワードも見直します。
  2. 「読むだけ」にしたいが、その選択肢が見つからない。 公式のヘルプセンターには、ツールごとの権限の設定は、TeamとEnterpriseのOwnerの機能として書かれています。個人のアカウントで同じ設定があるかは、確認できませんでした。見当たらないときは、使う場面を絞るか、切断します。
  3. 会話の中で、使ってほしくないコネクタが使われる。 公式のヘルプセンターには、会話ごとにコネクタをオンにしたときに、必要に応じて使われると書かれています。使わない会話では、オフにします。
  4. チャットを共有できない。 公式には、組織が「Share chats that use connectors」をオフにしていると、コネクタを使ったチャットは共有できない、と書かれています。管理者の設定です。

確認できなかったこと(個人のアカウントでの細かい権限設定、コネクタ経由のデータの保存や学習への使われ方)は、この記事では決めつけません。公式のヘルプセンターと、自分の画面で確かめてください。
