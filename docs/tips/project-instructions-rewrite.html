Projectの指示文を、動きを見ながら書き直す

Projectの指示文(Claudeに毎回読ませる前提)を、書きっぱなしにせず、決まった質問で動きを見て直す方法です。指示文に書くべきこと、Claudeからは見えないもの、共有したときに人から見えるものを、公式のヘルプで確かめた範囲で整理します。

要点は3つです。指示文は、決まった3つの質問で、前と後を見比べて直します。名前と説明の欄は、Claudeから見えないので、必要な前提は指示文に書きます。共有するProjectの指示文には、人に見せられないことを書きません。

Projectを作ったものの、「指示を書いたはずなのに、毎回の答えがばらつく」と感じている人向けです。たとえば、チームの問い合わせ返信を、Projectで下書きしている人です。直すたびに「良くなった気がする」で終わると、いつの間にか悪くなっていても気づけません。

ねらい

  • 指示文を、感覚ではなく、同じ質問での前後の比較で直します。
  • 指示文に入れるものと、資料に入れるものを分けます。
  • 共有やメモリで起こりうる、情報の漏れを防ぎます。

準備するもの

  • 指示文を設定済みのProject(まず、今の指示文をそのままコピーして保存します)。
  • そのProjectで、答えを見たい質問を3つ。「よくある質問」「少し難しい質問」「資料に書かれていない質問」の3種類にします。
  • 指示文を直したあとに、新しいチャットで試す時間。

手順

  1. 今の指示文を、別のメモに保存します。 公式のヘルプでは、指示は、Projectの画面で「Set project instructions」から書いて「Save instructions」で保存する、と書かれています。直したあとに、元に戻せるようにします。
  2. 3つの質問を決め、メモに書きます。 毎回、同じ文面で聞きます。
  3. Projectの中で、新しいチャットを始めて、3つの質問をします。 公式のヘルプには、指示はProject内のチャットに使われる、と書かれています。すでにあるチャットに、直した指示がすぐ反映されるかは、確認できませんでした。必ず新しいチャットで試します。
  4. 答えを、下の「見比べの表」に書きます。 良かった点と困った点を、1行ずつです。
  5. 指示文を、1か所だけ直します。 一度に複数を直すと、どの直しが効いたか分かりません。
  6. 新しいチャットで、同じ3つの質問をします。 前の表と見比べます。悪くなった質問があれば、直しを元に戻します。

画面の表示は変わることがあります。

指示文には、毎回守ってほしいこと(役割、答え方、分からないときの扱い)を書きます。長い資料や、よく変わる情報は、Projectの資料(ナレッジ)に入れます。公式のヘルプでは、Projectの名前と説明の欄について「Claudeはこれらの内容にアクセスできない」と書かれています。説明の欄にだけ書いた前提は、Claudeに伝わりません。

そのまま使えるプロンプト

実際の出力例

この記事を書いた環境では、読者のProjectと同じ条件で動かすことができませんでした。そのため、出力は載せません。作り話の出力を載せないためです。

自分のProjectで試すときの確かめ方です。

  • 「資料に書かれていない質問」で、推測せずに「資料にありません」と答えているかを見ます。推測で答えていたら、指示文に「資料にないことは、そう書く」の1行を足して、もう一度試します。
  • 「指示文のどの行に従ったか」の答えが、実際の指示文の行と合っているかを見ます。合っていないときは、その指示が守られていない可能性があります。
  • 直したあとに、元の指示文でうまくいっていた質問が悪くならなかったかを見ます。

使いどころと失敗例

向く場面は、同じProjectを何度も使い、答えの方向をそろえたいときです。たとえば、問い合わせの返信、議事録の整理、学習の相談です。

向かない場面は、1回きりの相談です。指示文を直す手間のほうが大きくなります。

安全面で気をつけることです。

  • 共有するProjectには、人に見せられないことを書きません。 公式のヘルプでは、共有はTeamとEnterpriseの説明に書かれています。「閲覧可」の権限でも、中身、資料、指示、チャットが見えると書かれています。Free、Pro、Max、Ultraでの共有については、確認できませんでした。
  • 個人情報や、社外に出せない情報を、指示文に直接書きません。 必要なら、「個人名は伏せる」のような扱いのルールだけを書きます。
  • メモリの影響に気づきにくい。 公式のヘルプには、Projectごとにメモリがあり、Projectの外のアカウントのメモリも使われる、と書かれています。ほかのProjectのメモリは使われません。ほかのProjectの影響を切り分けたいときは、Projectの画面で「Use account memory」を切ると書かれています。

よくある失敗と、その直し方です。

  • 指示が長くなりすぎて、守られない。 1つの指示を1行にして、優先度の低いものを削ります。
  • 直した所が複数で、何が効いたか分からない。 1周に1か所だけ直します。
  • 資料に書いてあるはずの内容を使わない。 質問に、資料の名前を入れて聞きます。

うまくいかないとき

  • 指示が反映されないとき: 新しいチャットで試しているかを確かめます。すでにあるチャットに反映されるかは、確認できませんでした。
  • 前のチャットの内容を覚えていないとき: 公式のヘルプには、Project内でも、チャットの間で文脈は共有されず、共有したい情報はProjectの資料に入れる、と書かれています。
  • 資料が増えて、答えの質が落ちたとき: 公式のヘルプには、有料プランでは、資料が上限に近づくと、自動で容量を広げる仕組みが働く、と書かれています。上限の数字は、確認できませんでした。使わない資料は外します。
  • 指示文を、直前の版に戻したいとき: 手順1で保存した元の版を、貼り直します。

つぎに試すなら

  • Projectsに資料と指示を入れて、毎回の説明をなくす

    同じ話題で何度もClaudeに相談するとき、背景の説明を毎回書き直さなくて済むように、資料と指示をProjectにまとめておく方法です。
