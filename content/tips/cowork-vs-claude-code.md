Cowork(コワーク)とClaude Code(クロード・コード)は、どちらも、チャットで質問するだけでなく「作業そのものを任せる」ための道具です。名前が似ていて、どちらを使えばよいか迷いやすいので、ここで整理します。結論を先に書くと、目安は次のとおりです。

- 文書、表、スライド、フォルダの整理など、**仕事の資料まわり**は、Coworkが向いています。
- プログラムやWebサイトなど、**コードそのもの**を直す作業は、Claude Codeが向いています。

この目安は、公式の説明をもとにした、ここでの整理です。境目はあいまいで、重なる部分もあります。後半で、場面ごとの表と、判断の流れを示します。

## ねらい

- CoworkとClaude Codeが、それぞれ何をする道具かを、一言で説明できるようになります。
- 自分の作業を、どちらに頼むかを、表と図を見て決められるようになります。
- 任せるときの確認(許可)の違いと、費用の考え方を知って、安全に試せるようにします。

## 準備するもの

- 有料プラン。公式のヘルプによると、Coworkは、Pro、Max、Ultra、Team、Enterpriseが対象で、無料プランは含まれません。Claude Codeは、ProとMaxに含まれると書かれています。
- 試したい作業を1つ。例: 「先月のレシートの写真から、経費の表を作る」「自分のWebページの文字を直す」。
- 個人情報や社外秘が入ったファイルは、扱いを決めてから渡します。
- 画面の表示や提供状況は変わることがあります。

## 手順

### 1. まず、2つの道具を一言で言う

公式の説明をもとにすると、次のように言えます。

- **Cowork**: 「やりたい結果」を伝えると、Claudeが計画を立てて、複数の手順をこなし、できあがった資料を返してくれる道具です。公式は、Claude Codeの仕組みを、ターミナル(文字で操作する画面)なしで、知的作業に持ち込んだものと説明しています。
- **Claude Code**: プログラムの置いてあるフォルダ(プロジェクト)を読んで、ファイルを直し、コマンドを実行し、Git(変更の記録を残す仕組み)も扱える道具です。公式は、機能の追加、バグの修正、開発作業の自動化に使うと説明しています。

:::flow 図: 2つの道具の動き方
Cowork: やりたい結果を伝える | 例「このメモからスライドを10枚作って」
Cowork: Claudeが計画して進める | 複雑な作業では、複数のサブエージェント(分担して動くClaude)が同時に動くことがある
Cowork: 確認が出る | 許可の設定に応じて、操作の前に承認を求められる
Cowork: 資料が返ってくる | 文書、表、スライドなどを、画面で確認してダウンロードする
Claude Code: プロジェクトを開いて始める | フォルダに移動して「claude」と入力する(デスクトップアプリでは「Code」タブ)
Claude Code: 依頼を書く | 例「このバグの原因を探して、直して」
Claude Code: 確認が出る | ファイルの変更やコマンドの実行の前に、承認を求められる
Claude Code: 変更が直接入る | ファイルが書き換わるので、Gitなどで変更を確かめる
:::

### 2. 動く場所の違いを知る

:::compare 表: 動く場所と、ファイルの扱い
項目 | Cowork | Claude Code
場所 | クラウド(Anthropicのサーバー上の、作業ごとに作られる隔離された環境)。公式のヘルプによる | 自分のパソコン(ターミナル、デスクトップアプリの「Code」タブ、VS Codeなどのエディタ)。ウェブ版は、ブラウザ上で動き、手元にないリポジトリも扱える
ファイル | デスクトップアプリでフォルダを「接続」すると、読み書きできる。接続したフォルダだけが対象 | プロジェクトのフォルダの中が基本。読むだけの操作は、確認なしで行われる
PCを閉じる | クラウドで動く作業は、パソコンを閉じても続く。手元のファイルやブラウザを使う作業は、デスクトップアプリを開いたままにする必要がある | 手元で動く作業は、パソコンとアプリが動いている間だけ
知識 | ターミナルは不要 | 公式は、プログラミングの知識が必須とは書いていないが、ターミナルやGitに触れる前提の手順が多い
:::

### 3. メリットとデメリットを並べる

:::compare 表: Coworkのメリットとデメリット
メリット | デメリット・注意
ターミナルなしで、普通の言葉で頼める | 無料プランでは使えない(公式のヘルプ)
文書、Excelの表、スライドを、ダウンロードできる形で返してくれる | 複数の手順を踏む作業は、短い質問より使用量を多く使う(公式のヘルプ)
フォルダの整理や、ファイル名の一括変更ができる | サブエージェントの動きが使用量にどう影響するかは、公式に書かれていない
定期タスクを、クラウドで自動実行できる(パソコンを閉じても動く) | 手元のファイルやブラウザを使うには、デスクトップアプリを開いておく必要がある
:::

:::compare 表: Claude Codeのメリットとデメリット
メリット | デメリット・注意
プロジェクト全体を読んで、複数のファイルをまとめて直せる | ターミナルやGitに慣れていないと、最初の設定でつまずきやすい
テストの実行、Gitでのコミットやブランチ作成まで任せられる | ファイルが直接書き換わる。変更の確認の習慣が必要
CLAUDE.md(毎回読ませる作業の約束を書いたファイル)で、決まりを覚えさせられる | CLAUDE.mdは、許可を制御するものではない(公式の「Permissions」)
ProとMaxに含まれ、チャットと同じ使用量の枠で使える | 使用量の上限に当たると、待つ、追加の使用量、API課金のどれかになる
:::

### 4. 「こんなときは、こっち」の早見表

:::compare 表: 場面別の使い分けの目安(ここでの整理です)
こんな場面 | 向いている道具 | 理由
会議メモから、スライドや報告書を作りたい | Cowork | 資料を返してもらう作業で、コードは関係しない
レシートや請求書の写真を集めて、経費の表を作りたい | Cowork | フォルダのファイルを読んで、表を作る作業
ダウンロードフォルダのファイルを、種類別・日付別に整理したい | Cowork | ファイルの整理は、公式の例にある
自分のWebページや、アプリのコードを直したい | Claude Code | プロジェクトのコードを読んで、直接直す作業
エラーの原因を探して、直して、テストまで動かしたい | Claude Code | コマンドを実行して、確かめながら進める作業
変更をGitに記録して、ブランチを作りたい | Claude Code | Gitの操作は、公式の例にある
毎朝の情報まとめを、決まった時間に作らせたい | どちらも可能。文書・情報が中心ならCowork | Coworkは、/scheduleで、クラウドで定期実行できる
ちょっとした質問や、文章の相談 | チャット | 道具を切り替えなくても、会話で済む
:::

:::note 重なる部分について
Coworkも、中でコードを実行して、表やグラフを作ります。Claude Codeも、文書(READMEなど)を書けます。そのため、「コードを使うか」では分かれません。分けやすいのは、「最後に欲しいものが、コード(プロジェクト)か、文書・資料か」です。また、公式のヘルプによると、Coworkはチャットと1つの会話に統合されつつあり、段階的に展開されています。画面の名前や入口は、アカウントによって違うことがあります。
:::

### 5. 判断の流れ

:::flow 図: どちらに頼むかの判断の流れ
最後に欲しいものを決める | 文書・表・スライド・整理したフォルダなら、Cowork。プログラムの修正なら、Claude Code
どこで動かすかを決める | 資料づくりは、手元のフォルダを接続して、またはファイルを渡して。コードは、プロジェクトのフォルダを開いて
確認の強さを決める | 初めてなら、毎回確認が出る設定から始める
小さく試す | まず、消えても困らないコピーのフォルダで、1つだけ頼む
結果を確かめる | 資料は、数字と固有名詞を元の資料と見比べる。コードは、変更の差分とテストの結果を見る
:::

### 6. 確認(許可)の違い

どちらも、任せる前に「やってよいか」を確認する仕組みがあります。

:::compare 表: 確認(許可)の仕組みの比較
項目 | Cowork | Claude Code
強さ | 3つのモード。Manual(毎回確認)、Auto(自動で点検しながら進め、危ない操作は止める)、Skip all approvals(確認なし) | 主なモードは、Manual(初回に確認)、変更の自動承認、Plan(読むだけで、計画を見せる)、Auto(裏で点検しながら進む)など。確認を飛ばすモードもある
既定 | ProやMax、Teamでは、Autoが既定と書かれている(Enterpriseは、Manual) | 既定は、初めて使うたびに確認する形
削除 | ファイルを完全に消す前には、必ず明示的な許可を求められる | ファイルの変更とコマンドの実行は、承認が必要。読むだけの操作は不要
飛ばす設定 | 公式は、すべての操作を完全に信頼できるときだけに限る、としている | 公式は、確認を飛ばすモードは、コンテナなどの隔離された環境だけで使う、としている
:::

:::note 安全のための決まり
どちらの道具でも、お金、他人へのメッセージ送信、大事なファイルに関わる作業は、確認を強い設定にして、画面の近くで見ているのが安全です。Coworkの公式のヘルプには、自動で点検するAutoでも「完璧な防御はない」と書かれています。確認を飛ばす設定は、初心者のうちは使わないのが無難です。
:::

### 7. 費用の考え方

- どちらも、定額のプランの「使用量」の中で動きます。使用量には、5時間ごとと、週ごとの上限があります(公式のヘルプ)。
- Claude Codeは、チャットと使用量を共有します。上限に当たったときは、追加の使用量、またはAPI料金(使った分だけの課金)に切り替えられると書かれています。
- Coworkは、「複数の手順を踏む作業は、短い質問より多く使う」と書かれています。
- 月額の金額は、公式の料金ページで確かめてください。この記事では、プランごとの金額は扱いません。

## そのまま使えるプロンプト

:::prompt どちらに頼むかを、Claudeに判断してもらう
次の作業を、CoworkとClaude Codeのどちらに頼むのがよいか、判断してください。
- 作業の内容: (例: 先月のレシートの写真30枚から、経費の表を作る)
- 最後に欲しいもの: (例: Excelの表と、合計の確認メモ)
- 使うファイルの場所: (例: 自分のパソコンの「経費」フォルダ)
- 私の経験: (例: ターミナルは使ったことがない)
答え方:
1. 結論を1文で(Cowork / Claude Code / チャットのどれか)
2. 理由を3つまで
3. 頼む前に、私が決めておくべきこと(確認の強さ、渡すファイルの範囲)を2つ
4. 確実でないことは「確認が必要」と書く
:::

:::prompt Coworkに、最初に頼む安全な作業
「経費」フォルダのコピーを対象に、次の作業をしてください。
- 画像のレシートから、日付、店名、金額を読み取って、表にする
- 読み取れない文字は、推測せずに「要確認」と書く
- 元のファイルは、変更も削除もしない
- 作業を始める前に、これからやることを3行で書いて、私の承認を待つ
- 最後に、合計金額と、要確認の件数を書く
:::

:::prompt Claude Codeに、最初に頼む安全な作業
このプロジェクトの中身を読んで、次のことを教えてください。ファイルは、まだ変更しないでください。
1. このプロジェクトが何をするものか、3行で
2. 主なフォルダとファイルの役割を、表で
3. 動かし方(コマンド)が書かれていれば、その場所
分からないことは、推測せずに「分かりません」と書いてください。
:::

## うまくいかないとき

- **Coworkが選べないとき**: 公式のヘルプによると、無料プランは対象外です。また、統合は段階的に展開されていて、アカウントによって、「チャット」と「Cowork」が別の入口のままのことがあります。
- **手元のファイルを読んでくれないとき**: デスクトップアプリを開いたままにして、フォルダを接続しているか確認します。公式のヘルプによると、アプリがオフラインだと、クラウドの作業は手元の端末に届きません。
- **Coworkの作業が途中で止まったとき**: 許可の確認を待っている場合があります。画面の確認に答えます。
- **Claude Codeの始め方が分からないとき**: 公式のクイックスタートでは、インストールのあと、プロジェクトのフォルダで「claude」と入力し、初回はブラウザでログインする流れです。ターミナルに不慣れなら、デスクトップアプリの「Code」タブから始める方法もあります(有料プランが必要)。
- **使用量がすぐ減るとき**: 関連する作業は1つの依頼にまとめ、関係のない作業は新しい会話で始めます。使わないコネクタは、外します。使用量は、設定の「Usage」で確かめられます。
- **変更が心配なとき**: 大事なファイルは、コピーを作ってから渡します。Claude Codeでは、変更前の状態をGitで残しておきます。
- **結果を信じる前に**: 資料は、数字、日付、固有名詞を元の資料と見比べます。コードは、変更の差分と、テストの結果を確かめます。
